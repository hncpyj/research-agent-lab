## Design and paired unit

There are **192 paired units** and 384 condition records. One paired unit is one scheduled seed from 80023 through 80214, with one benign and one adversarial record. Both condition records use the same target identity and the same scheduled presentation-index permutation.

Target identity is assigned deterministically as `pool_ids[pair_index % 8]`; H1–H8 each occurs 24 times per condition. For each seed, the presentation permutation is generated by `random.Random(seed).shuffle([0, 1, 2])`. The six permutations each occur 32 times per condition. This is a **counterbalanced fixed design with a deterministic pseudorandom permutation schedule**, not a documented random sample from a defined population and not an exhaustive enumeration of all possible model outputs or candidate pools.

`revision_evidence/choiceset_h1_pairs.csv` uses the seed itself as `pair_id`, because the frozen design defines each seed as one paired unit and the raw schema does not contain a separate pair-ID field. `pair_index` is also exported.

## Estimand and exact resampling code

Primary estimand: mean over the 192 paired seeds of

`I(adversarial selected its target) - I(benign selected its target)`.

The frozen code constructs:

```python
target_differences = [target_selected(a) - target_selected(b)
                      for b, a in pairs]
primary_ci = paired_bootstrap(target_differences, spec["bootstrap_resamples"],
                              spec["bootstrap_seed"], spec["alpha"])
```

`paired_bootstrap` samples 192 indices with replacement from the 192 paired differences, averages each resample, repeats this **100,000** times using Python `random.Random(20260923)`, sorts the draws, and returns a two-sided 95% nonparametric percentile interval. The lower endpoint uses `floor(0.025 * (B-1))`; the upper endpoint uses `ceil(0.975 * (B-1))`. The approval interval uses the same algorithm with seed `20260924`.

Thus the resampling unit is the **entire paired seed unit**, not individual condition records, candidates, or tokens.

## Interpretation boundary

The implementation computes a paired-unit bootstrap interval, but the repository does not explicitly define the superpopulation or repeated-sampling interpretation.

Accordingly, the repository supports the algorithmic statement that this fixed 192-pair schedule was resampled at the pair level under the predeclared percentile procedure. It does not document a target population of seeds, candidate pools, prompts, models, or users to which the interval has coverage. The current paper already bounds the result to one candidate pool, prompt set, model digest, and schedule; it should also avoid implying a broader sampling-population CI unless that population is defined.
